# silky-recorder

**Автоматически записывает красивое обучающее видео вашего сайта.**

Вы один раз описываете, что показать, — а программа сама открывает сайт,
плавно водит курсором, кликает, печатает, приближает нужное, показывает подписи,
читает их вслух голосом диктора, добавляет звуки клика и фоновую музыку
и сохраняет готовый `mp4`.

Не нужны ни программа для записи экрана, ни видеоредактор.
Всё делается автоматически и в фоне — во время записи компьютером можно пользоваться.
Работает на **любом сайте** (не только на каком-то конкретном).

Дальше — по порядку. Просто читайте сверху вниз.

---

## Сначала разберёмся, что такое «сценарий»

Сценарий — это обычный текстовый файл (`.json`), в котором вы **списком** описываете, что показать.
Файл состоит из двух частей: `meta` (общие настройки) и `steps` (шаги — что делать по очереди).

Вот маленький пример целиком:

```json
{
  "meta": {
    "title": "Как найти статью",
    "url": "https://ru.wikipedia.org/wiki/Заглавная_страница",
    "auth": { "type": "none" },
    "out": "out/demo.mp4"
  },
  "steps": [
    { "type": "title",   "text": "Как найти статью", "hold": 2500 },
    { "type": "caption", "text": "Вводим запрос в поиск", "read": 2500 },
    { "type": "click",   "target": "input[name=\"search\"]" },
    { "type": "type",    "target": "input[name=\"search\"]", "text": "Кошка" },
    { "type": "key",     "key": "Enter" },
    { "type": "outro",   "text": "Готово!", "hold": 2500 }
  ]
}
```

Читается как инструкция: покажи заголовок → покажи подпись → кликни в поиск → напечатай «Кошка» → нажми Enter → покажи финал.

**`meta` — общее:**

- `title` / `subtitle` — что написать на заставке в начале.
- `url` — с какой страницы начинать.
- `auth` — как войти в аккаунт (для сайтов с логином; для публичных — `{ "type": "none" }`).
- `out` — куда сохранить видео.

**`steps` — шаги.** Каждый шаг — одна строчка вида `{ "type": "...", ... }`. Самые нужные:

| Шаг | Пример | Что делает |
|--|--|--|
| `title` / `outro` | `{ "type": "title", "text": "Заголовок", "hold": 2500 }` | заставка в начале / в конце |
| `caption` | `{ "type": "caption", "text": "Подпись", "read": 2500 }` | подпись снизу (держится `read` мс) |
| `click` | `{ "type": "click", "target": "button.save" }` | кликнуть по элементу |
| `type` | `{ "type": "type", "target": "input#q", "text": "текст" }` | напечатать в поле |
| `key` | `{ "type": "key", "key": "Enter" }` | нажать клавишу (напр. отправить форму) |
| `zoom` | `{ "type": "zoom", "target": ".card", "scale": 1.4 }` | приблизить элемент и вернуть |
| `scroll` | `{ "type": "scroll", "target": ".footer" }` | прокрутить к элементу |
| `hover` | `{ "type": "hover", "target": ".row", "zoom": 1.5 }` | навести курсор (можно с зумом) |
| `say` | `{ "type": "say", "text": "Реплика диктора" }` | сказать голосом без подписи на экране |

**Как указать элемент (`target`)** — два простых способа:

- **По тексту** (проще, если не знаете вёрстку): `{ "text": "Сохранить" }` — найдёт элемент с таким текстом.
- **По CSS-селектору** строкой: `"button.save"`, `'input[name="search"]'` (как в инструментах разработчика браузера).

Полный список шагов и параметров — в **`scenarios/FORMAT.md`**.
Готовый большой пример — **`scenarios/wikipedia.json`**.

> Не хотите писать сценарий руками? Можно **описать его словами ИИ-агенту** — см. раздел ниже.

## Что нужно один раз проверить

Нужен **Node.js версии 18 или новее**. Проверьте в терминале:

```bash
node -v
```

Если видите номер версии — всё хорошо. Если команда не найдена — установите Node.js (кнопка **LTS**) с https://nodejs.org.

---

## Шаг 1. Установка (один раз)

```bash
git clone <адрес этого репозитория>
cd silky-recorder
npm install
```

`npm install` скачает библиотеки и браузер Chromium. 1–3 минуты, **только первый раз**.

> Если в конце ошибка про Chromium — выполните `npx playwright install chromium`.

---

## Шаг 2. Запишите готовый пример

Пример работает сразу — это публичная Википедия, вход не нужен:

```bash
node bin/silky.mjs record scenarios/wikipedia.json
```

Через пару минут в терминале будет:

```
✓ Готово за 59с → out/wikipedia.mp4
```

Откройте `out/wikipedia.mp4` — увидите, как выглядит результат.

Полезные флаги (не обязательны):

```bash
node bin/silky.mjs record scenarios/wikipedia.json --headed   # показать браузер
node bin/silky.mjs record scenarios/wikipedia.json -v         # печатать шаги
```

---

## Шаг 3. Сделайте своё видео

Скопируйте пример и меняйте под себя:

```bash
cp scenarios/wikipedia.json scenarios/my.json
```

Откройте `scenarios/my.json`, поменяйте `meta.url` на свою страницу и опишите `steps`
(по таблице выше и `scenarios/FORMAT.md`). Затем запишите:

```bash
node bin/silky.mjs record scenarios/my.json
```

**Если ваш сайт требует входа в аккаунт** — сначала войдите один раз:

1. В сценарии поставьте `"auth": { "type": "state", "file": "auth/state.json" }`.
2. Выполните:
   ```bash
   node bin/silky.mjs login scenarios/my.json
   ```
   Откроется браузер — войдите как обычно, потом **нажмите Enter в терминале или просто закройте окно браузера**.
   Сессия сохранится и будет переиспользоваться. Входить заново нужно только когда сессия истечёт.

## Не хотите писать сценарий руками? Опишите его ИИ-агенту

В репозитории есть **навык `scenario-author`** для ИИ-агента (Claude Code).
Вы даёте описание **свободным текстом** — агент сам изучает ваш сайт (через Playwright),
подбирает правильные селекторы и собирает готовый сценарий в нужном формате.

Пример (в Claude Code, открытом в папке проекта):

> Используя навык scenario-author, собери сценарий для https://мой-сайт/страница:
> «Показать, как создать заказ: открыть каталог, добавить товар в корзину, оформить».

Агент вернёт готовый `scenarios/*.json`, который сразу можно записать командой из Шага 2.
Подробности навыка — в `.claude/skills/scenario-author/SKILL.md`.

## Если что-то пошло не так

| Проблема | Что сделать |
|--|--|
| `Chromium not found` | `npx playwright install chromium` |
| В ролике страница логина / нет данных | Сессия истекла — повторите вход: `silky login <сценарий>` |
| `click fail` / «элемент не найден» | Проверьте `target` (текст/селектор). Запустите с `--headed`, чтобы увидеть, где застряло |
| В кадр лезет лишний баннер/блок | Добавьте его CSS-селектор в `meta.hide`, напр. `"hide": [".cookie-banner"]` |
| Громкость музыки/звуков не та | В `meta`: `music.vol` (0..1), `sfx.clickVol`, `sfx.keyVol` |
| Ошибка при озвучке | Сервис синтеза временно недоступен — повторите запуск (готовые реплики берутся из кэша). Не помогло — `npm i node-edge-tts@latest` |
| Голос звучит поверх музыки слишком тихо | В `meta.voice`: поднимите `vol` или уменьшите `duck` (сильнее приглушать музыку) |

## Добавить голос диктора

Ролик может сам себя озвучивать: текст подписей читается вслух синтезированным голосом.
Ничего доустанавливать не нужно — всё уже пришло с `npm install`.

Добавьте в `meta` вашего сценария одну строку:

```jsonc
"voice": { "name": "ru-RU-SvetlanaNeural" }
```

Всё. Теперь текст шагов `title`, `caption` и `outro` будет прочитан вслух,
а музыка сама приглушится под голосом и вернётся после.

Голоса на выбор (русских два — женский и мужской):

```bash
node bin/silky.mjs voices ru-RU
```

**Подписи короткие, а речь — нормальная.** На экране хорошо смотрится короткий тост,
а в наушниках — целое предложение. Для этого есть поле `say`:

```jsonc
{ "type": "caption", "text": "Открываем статью", "read": 2000,
  "say": "Нажимаем Enter, чтобы открыть статью." }
```

- `"say": "..."` — прочитать не то, что написано на экране, а вот это.
- `"say": false` — на этом шаге промолчать.
- `{ "type": "say", "text": "..." }` — реплика вообще без подписи на экране.
- `say` можно ставить на любом шаге — например, комментировать клик или прокрутку.

**Паузы подстраиваются сами.** Программа заранее знает, сколько длится каждая реплика,
поэтому шаг не закончится, пока диктор не договорит. Значения `read` и `hold`
в сценарии становятся *минимумом*: подписи больше не уезжают на полуслове.

**Второй раз — быстро и без интернета.** Каждая реплика озвучивается один раз и остаётся
в папке `voice/`. Повторная запись того же сценария голос заново не запрашивает.

Тонкая настройка (темп, громкость, насколько приглушать музыку) — в `scenarios/FORMAT.md`.

> Озвучка идёт через тот же сервис, что и кнопка «Прочитать вслух» в браузере Microsoft Edge.
> Он бесплатный, но неофициальный: иногда меняется на стороне Microsoft. Если синтез перестал
> работать — обновите пакет: `npm i node-edge-tts@latest`. Уже озвученные реплики
> при этом останутся в кэше и не потеряются.

## Заменить музыку или звуки

По умолчанию — файлы из `assets/` (`music.mp3`, `click.wav`, `key.wav`).
Свои — положите файлы и укажите пути в сценарии:

```jsonc
"music": { "file": "assets/моя-музыка.mp3", "vol": 0.85 },
"sfx":   { "click": "assets/мой-клик.wav", "key": "assets/моя-клавиша.wav" }
```

---

## Другие способы входа

По умолчанию — **«войти один раз»** (`auth.type: "state"`), см. Шаг 3. Есть и другие (подробности — `scenarios/FORMAT.md`):

- **`token`** — токен приложения из переменной окружения `AUTH_TOKEN`.
- **`cdp`** — переиспользовать уже открытый Chrome (запущенный с `--remote-debugging-port=9222`).
- **`none`** — сайт без входа.

---

## Как это устроено (для любопытных)

1. Все реплики озвучиваются заранее, до открытия браузера, и складываются в кэш.
   Поэтому длительность речи известна ещё до съёмки — по ней и выставляются паузы.
2. Поднимается чистый браузер (Chromium) с вашей сессией и включённой записью видео.
3. В страницу добавляется движок анимации (курсор/зум/подписи) и выполняются шаги сценария;
   при переходе на новую страницу движок переинжектится сам.
4. ffmpeg подмешивает голос, музыку и звуки клика/клавиш по таймингам действий,
   приглушает музыку под репликами и сохраняет `mp4`.

Работает на **macOS, Windows и Linux** (нужен только Node.js — остальное ставит `npm install`).
