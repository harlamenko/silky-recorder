# scenario-author

Задача: превратить **свободное описание** туториала в **готовый файл сценария**
`scenarios/<name>.json` для этого репозитория (silky-recorder), которым потом
пишется видео командой `node bin/silky.mjs record scenarios/<name>.json`.

Работай из **корня репозитория** (там `bin/`, `src/`, `scenarios/`).

## Что нужно от пользователя

- **URL** стартовой страницы.
- **Описание** словами: что показать, по шагам или прозой.
- Если сайт с логином — способ входа (см. `auth` ниже).

Если чего-то не хватает (URL, вход) — коротко спроси.

## Процедура

1. **Прочитай формат.** Открой `scenarios/FORMAT.md` — там типы шагов и способы указания `target`.
   Готовый образец — `scenarios/wikipedia.json`.

2. **Изучи сайт — не угадывай селекторы.** Запусти разведчик:
   ```bash
   node .claude/skills/scenario-author/inspect.mjs "<URL>" [--state auth/state.json | --token <VALUE>]
   ```
   Он вернёт JSON с полями, кнопками, ссылками, заголовками и предложенными `target`.
   Если для нужных шагов страница другая (напр. после перехода/логина) — прогони inspect по тем URL тоже.
   Можно также воспользоваться доступными инструментами Playwright/DevTools, если они есть.

3. **Собери шаги.** Переведи описание в `steps` (см. таблицу в FORMAT.md). Правила:
   - Перед каждым действием давай **`caption`** с понятным текстом (что сейчас произойдёт) — это ведёт зрителя.
   - Ритм неспешный: `caption.read` ≈ 2400–2900, паузы `after` ≈ 700–3000, `zoom.hold`/`hover.hold` ≈ 2600–3600.
   - `target` выбирай **устойчивый**: предпочитай `{ "text": "…" }`, `input[name="…"]`, `input[placeholder="…"]`;
     для строк SPA-таблиц — `{ "id": "…" }` (из `idRows`); избегай хрупких `nth-child`/автогенерённых классов.
   - Навигацию (клик по ссылке/кнопке или `Enter`) поддерживай — движок переинжектится сам; после перехода
     инспектируй новую страницу для следующих селекторов.
   - Ключевые моменты подчёркивай `zoom`/`hover` (напр. «вот результат — записалось»).
   - Начни с `title`, закончи `outro`.

4. **Собери `meta`:**
   - `title`, `subtitle`, `url`, `out` (`out/<name>.mp4`).
   - `auth`: `none` (публичный) / `{type:"state","file":"auth/state.json"}` (логин один раз) /
     `{type:"token","env":"AUTH_TOKEN"}` / `{type:"cdp",...}`. Пароли НЕ вписывай в файл.
   - `hide`: массив CSS лишних баннеров/оверлеев, если мешают кадру.
   - `music`/`sfx`: по умолчанию `assets/music.mp3`, `assets/click.wav`, `assets/key.wav` (можно опустить — возьмутся дефолты).

5. **Запиши файл** `scenarios/<name>.json` и **проверь, что это валидный JSON**
   (`node -e "JSON.parse(require('fs').readFileSync('scenarios/<name>.json','utf8'))"`).

6. **Проверь на деле (если есть доступ/вход):** прогони запись
   `node bin/silky.mjs record scenarios/<name>.json -v`, при желании вытащи 2–3 кадра ffmpeg'ом
   и убедись, что нужные элементы находятся. Если шаг не нашёл элемент — поправь `target` и перезапиши.

## Итог

Верни пользователю путь к готовому `scenarios/<name>.json` и команду для записи.
Кратко перечисли, какие шаги получились, и отметь, если для какого-то элемента селектор пришлось выбрать «на глаз» (стоит проверить).
